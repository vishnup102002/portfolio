PROJECT: LEGALMIND — ASYMMETRICAL JUSTICE ENGINE & GraphRAG

Core Idea: LegalMind is a production-grade AI system designed to bridge legal equity for low-literacy and marginalized populations. It converts unstructured regional voice notes (Malayalam/English) into deterministic, legally grounded audio roadmaps and verified printable PDF notices.

Stack: LangGraph, Neo4j (GraphRAG statutory trees: Statute → Section → Case Precedent), Qdrant Cloud (dense + BM25 hybrid vector search), Groq (llama-3.1-8b-instant), Twilio WhatsApp API, RAPTOR hierarchical trees, FastAPI, gTTS, Shrutam-2 STT, Sooktam-2 TTS.

Voice-to-Voice Gateway: Operates an audio pipeline — Shrutam-2 Speech-to-Text streaming → Qwen-2.5 intent extraction → slot filling (incident_type: illegal_eviction) → localized Malayalam speech rendering for illiterate accessibility. Supports bidirectional WhatsApp voice notes via Twilio.

Citation Faithfulness Shield: Programmatic verification gate that evaluates context similarity and grounding metrics. If context score is less than 0.72, the system short-circuits with an UNVERIFIED_LEGAL_GROUNDS safety fallback, preventing fictitious law generation and hallucinations.

IRAC Format Deliverables: Formats output using the legal IRAC framework (Issue, Rule, Application, Conclusion). Synthesizes a simplified layperson audio roadmap for WhatsApp voice note delivery and compiles a formal PDF legal notice (ReportLab/WeasyPrint) for direct WhatsApp document attachment.

LLM-as-a-Judge Evaluation Harness: 12-scenario automated evaluation (English & Malayalam) across 5 metrics — Faithfulness (>=0.70), Relevance (>=0.80), Language Compliance (>=0.90), Hallucination Rate (<=0.10), Completeness (>=0.80).

Infrastructure: Designed for cost-sovereignty. Runs on AWS EC2 Free Tier t2.micro (1GB RAM + 2GB Swap space) by delegating state and vectors to serverless cloud tiers (Neo4j AuraDB free tier & Qdrant Cloud free tier) with Nginx proxying and systemd service management.

WhatsApp Integration: Stateful phone-number-based session management (whatsapp_session.py), auto-transcription of voice notes, TTS audio roadmap synthesis, and PDF notice delivery via Twilio Media API.

Key Modules: config/ (Neo4j schemas), data/ingestion/ (Playwright legal portal scrapers), data/processing/ (RAPTOR hierarchical clustering), database/graph_store.py (Neo4j Cypher compilers), database/vector_store.py (Qdrant hybrid search), audio/stt_gateway.py (Shrutam-2), audio/tts_renderer.py (Sooktam-2), app/pipeline.py (LangGraph state machine), app/server.py (FastAPI + Twilio webhooks), app/evaluator.py (LLM-as-a-Judge framework).

Status: Core LangGraph orchestration and hybrid retrieval (Neo4j + Qdrant) are functional. Currently debugging voice-to-voice Twilio pipeline latency. In progress.

PROJECT: GESTURELEARN — REAL-TIME COLLABORATIVE GESTURE WORKSPACE

Core Idea: Low-latency collaborative presentation platform merging WebRTC video conferencing with edge computer vision (Google MediaPipe Hands). Users draw, erase, and navigate using natural 3D hand gestures in the browser.

Stack: React 18, TypeScript, WebRTC (RTCPeerConnection with STUN/TURN), Socket.io (sub-50ms event relay), MediaPipe Hands (21 3D landmarks, client-side Wasm/GPU), Express/Node.js backend, Vite, Tailwind CSS + shadcn-ui.

Flipped Coordinate Space Solution: Solved WebRTC video mirroring coordinate alignment by performing a hard horizontal flip on an off-screen canvas at 30 FPS (canvas.captureStream(30)), running MediaPipe inference on the raw un-flipped feed, and mapping normalized coordinates as flippedNormX = 1.0 - rawNormX so local and remote canvas overlays align perfectly without CSS inversion bugs.

5-Gesture Command State Machine:
- L-Shape/Gun (Index up, Thumb out): Draw strokes on local & remote canvases.
- Flat Palm (All 5 fingers extended): Erase mode (60px brush footprint).
- Fist (All fingers folded, 2-second hold): Clear entire canvas.
- Pinch (Index + Thumb touching): Hover cursor mode.
- Peace/Select (Index + Middle up): Color palette overlay.

100% client-side WebAssembly vision processing. Zero camera video frames are ever transmitted to external servers. All streams are encrypted P2P via WebRTC DTLS/SRTP.

Deployed: Frontend on Vercel, backend on Render.com via Docker container.

PROJECT: DXF → JSON AGENTIC INDOOR NAVIGATION PIPELINE (agentpipeline)

Core Idea: Built during R&D internship at Bluecast Technologies. Converts complex hospital CAD floor plans (.dxf files) into structured, directional navigation JSON schemas powering real-time indoor turn-by-turn navigation engines.

Stack: Python, ezdxf, Shapely, GPT-4o, custom geometric vector algorithms.

75% API Cost Reduction Cascade:
- Pre-detects corridors and vertical nodes (lifts, staircases, escalators) using pure geometry and spatial clustering — zero LLM tokens used.
- Classifies standard spaces via regex dictionary/word-boundary keyword tables.
- Only sends unclassified, ambiguous room labels to GPT-4o in a single compressed batch call.

3-Pass Door & Spatial Graph (geometry.py):
- Pass 1: Links rooms to corridors via physical DXF door block inserts.
- Pass 1.5: Prunes false-positive phantom room-to-room links if both rooms already connect to corridors.
- Pass 2: Connects en-suite rooms sharing walls using adaptive geometric thresholds derived from the building's own scale.
- Pass 3: Bounding-box proximity fallbacks for isolated rooms.

Directional Neighbor Resolution: Computes entry vectors from door blocks inward to room centroids, resolving exact spatial positions (left, right, front, behind) using dot product and cross product calculations.

Navigation Enrichment Layer: Enforces bidirectional symmetry, infers building zones (Imaging, Emergency, Admin), generates display names and room aliases, assigns system confidence scores (0.60-0.95) per entity.

Multi-Floor Pipeline: Matches vertical nodes across floors by name similarity + coordinate proximity, interpolates intermediate floors.

Key Modules: parser.py (DXF reader + coordinate normalization), agent.py (ReAct classification loop), geometry.py (spatial relationship engine), navigation_enrichment.py (zone inference, aliases, corridor connectivity), run_pipeline.py (single-floor CLI), multi_floor_pipeline.py (multi-floor CLI), schema_validator.py.
